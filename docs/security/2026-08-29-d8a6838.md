## Summary

The codebase is disciplined — no committed secrets, a hardened worker image, zod-validated
inputs. The material risk is concentrated in two places: a fallback secret that becomes a real
key on any misconfigured deploy (**F1**), and an unrestricted outbound `fetch` in the worker
(**F2**). Both should be fixed before the next production deploy.

`F3` and `F5` compound: the public API has no rate limiting and exposes more than the curated
routes suggest.

## High severity

### F1 — Hardcoded fallback for `PAYLOAD_SECRET`

- **Where:** `apps/web/src/payload.config.ts:40`, `apps/web/scripts/ensure-schema.mjs:17`
- **Code:**

  ```ts
  secret: process.env.PAYLOAD_SECRET || 'dev-secret-change-me',
  ```

- **What:** If `PAYLOAD_SECRET` is ever unset in a deployed environment, Payload signs its auth
  JWTs and session cookies with a constant that is published in this repository. The same
  silent-empty pattern applies to `DATABASE_URL || ''` on line 47, and `ensure-schema.mjs` sets
  `PAYLOAD_SECRET ||= 'build-time-schema-push'`.
- **Impact:** Anyone can forge a valid admin session token and take over the CMS — full
  read/write to every collection, user creation, API-key issuance.
- **Fix:** Throw on startup when `PAYLOAD_SECRET` or `DATABASE_URL` is missing and
  `NODE_ENV === 'production'`. Never ship a literal fallback secret; keep the build-time schema
  push path clearly separated since it never serves traffic.

### F2 — Server-side request forgery via `MonitoredSources.rssUrl`

- **Where:** `apps/worker/src/adapters/rss.ts:18`, `packages/shared/src/index.ts:68`
- **Code:**

  ```ts
  const res = await fetch(input.rssUrl);
  // isValidHttpUrl() only checks: url.protocol === 'http:' || 'https:'
  ```
  
- **What:** `rssUrl` is user-supplied — `MonitoredSources` has `create/update: isAuthenticated`,
  which includes `worker`-role accounts. The only validation is a protocol check; there is no
  block on `localhost`, RFC-1918 ranges, or `169.254.169.254`. The worker runs on Cloud Run.
  Redirects are followed without re-validation.
- **Impact:** The worker can be pointed at the cloud metadata endpoint (service-account token
  theft), internal-only services, or arbitrary internal ports for scanning. Feed content that
  parses as XML also surfaces as publication titles/abstracts, giving a limited read-back
  channel.
- **Fix:** Resolve the hostname and reject private / loopback / link-local addresses before
  fetching; re-check on every redirect hop and cap the hop count. Prefer an explicit allowlist
  of feed hosts or route all adapter traffic through an egress proxy. Add a request timeout and
  a response-size limit.

## Medium severity

### F3 — Unauthenticated AI cost & write amplification

- **Where:** `apps/web/src/app/api/public/publications/[id]/route.ts`
- **What:** A public, unauthenticated `GET` with `?locale=` triggers `translateSummary()` — an
  AI-gateway call — plus a `payload.create()` on every cache miss. Iterating publication IDs
  across the four target locales lets an anonymous caller drive LLM spend and create rows at
  will. No `/api/public/*` route, nor the Payload REST/GraphQL endpoints, has any rate limiting.
- **Impact:** Direct financial cost (AI gateway) and unbounded row growth in
  `content-translations`; general DoS surface on the public API.
- **Fix:** Rate-limit the public API (Vercel BotID, middleware token bucket, or a KV counter
  keyed by IP). Move translation generation into the worker pipeline so reads only ever serve
  cached rows, and cap cost per client per day.

### F4 — Stored XSS via `originalUrl` rendered as `href`

- **Where:** `apps/web/src/app/[locale]/projects/[slug]/publications/[publicationId]/page.tsx:60`,
  `apps/worker/src/adapters/rss.ts:49`
- **Code:**

  ```tsx
  <Anchor href={pub.originalUrl} target="_blank" rel="noopener noreferrer">
  ```

- **What:** For RSS-sourced publications, `originalUrl` is `item.link` taken straight from the
  feed and stored unvalidated. A feed can supply a `javascript:` URI; React and Mantine do not
  sanitise `href`.
- **Impact:** Script execution in a visitor's session when they click the "original link".
  Requires a malicious or compromised feed to be configured as a source, and a user click —
  hence medium, not high.
- **Fix:** Validate that `originalUrl` is `http(s)` at ingestion in the worker, and again at
  render. Drop or neutralise anything else.

### F5 — Public read is broader than the curated API implies

- **Where:** `collections/Publications.ts`, `Digests.ts`, `ResearchProjects.ts`,
  `ContentTranslations.ts`; `app/(payload)/api/[...slug]`, `app/(payload)/api/graphql`
- **What:** Those collections set `read: publicRead` (`() => true`). The hand-written
  `/api/public/*` routes carefully project a handful of safe fields — but
  `GET /api/publications`, `/api/digests`, `/api/research-projects` and the GraphQL endpoint
  return everything to anonymous callers: full `abstractOrBody` text, publications not yet in
  any published digest, and project `keywords`, `owner`, `lastSuccessfulRunAt`,
  `bootstrapLookbackDays`, `emailNotificationEnabled`.
- **Impact:** Information disclosure. The curated routes create a false sense of control over
  what is public, and full third-party abstracts may carry copyright exposure.
- **Fix:** Decide explicitly what is public. Replace `publicRead` with an access function that
  filters publications to those in a published digest and limits project fields; disable
  GraphQL if it is unused, or lock down field-level access.

## Hardening

| #   | Item                                                                                                                                                                                                                                                                                                                                                                |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| H1  | **Prompt injection from external content.** Titles and abstracts are concatenated into the `classifyRelevance` / `summarizeAndRank` prompts with no delimiting, so a crafted abstract can flip relevance or importance and poison summaries. Wrap untrusted text in clear delimiters and instruct the model to treat it as data. — `apps/worker/src/pipeline/ai.ts` |
| H2  | **No ownership check on `manualRun`.** The endpoint is gated only by `isAuthenticated`; any staff user can trigger runs against any project, though the `owner` field implies otherwise. — `apps/web/src/endpoints/manualRun.ts:14`                                                                                                                                 |
| H3  | **`assertLinkOnlyEmail` is never called.** `sendDigestPublishedEmail` never invokes it, so the "link-only, no content in the email" guarantee is not enforced at send time. — `apps/worker/src/notify/digestEmail.ts`                                                                                                                                               |
| H4  | **Shared static bearer secret.** `X-Payload-API-Key` is a single unscoped secret with write access, compared with `===` (not constant-time) and sent as a custom header that is easy to log. Prefer Payload's native per-user API keys (already enabled via `useAPIKey`); at minimum use `crypto.timingSafeEqual`. — `apps/web/src/access/index.ts:32-34`           |
| H5  | **User enumeration by worker accounts.** `Users` has `read: isAuthenticated`, so a `worker`-role account can list every admin user and email address. Scope read to `isAdmin` or to self. — `apps/web/src/collections/Users.ts`                                                                                                                                     |
| H6  | **Over-permissive field access.** `ResearchProjects.hasPublishedDigest` sets field `access.update: () => true`. Harmless today because the collection-level gate still holds, but fragile — tighten it to worker/admin. — `apps/web/src/collections/ResearchProjects.ts:141`                                                                                        |

## Done well

- No secrets committed — `.env*` is gitignored and only `.env.example` is tracked.
- Worker container is hardened: distroless runtime, non-root, `--frozen-lockfile`, `apt upgrade`
  in build stages, `--ignore-scripts` for production deps.
- Public route query parameters are validated with zod schemas (`LocaleSchema`,
  `ImportanceSchema`) before use.
- The header API-key path is correctly disabled when `PAYLOAD_API_KEY` is unset
  (`Boolean(expected && headerKey && …)`).
- `canUpdateResearchProject` correctly restricts a header-only key to writing just the
  `lastSuccessfulRunAt` field.
- Missing `AI_GATEWAY_API_KEY` throws rather than silently degrading.

## Coverage & caveats

Static read of application source only. **Not covered:** dependency CVE scan (`pnpm audit` /
OSV), dynamic testing against a running instance, authentication flows end to end,
infrastructure and IAM configuration (Cloud Run, Neon, Vercel project settings), rate-limit
behaviour under load, and Payload admin CSRF / session cookie configuration.
